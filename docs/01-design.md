# 01 · 设计规范

本文是**约束性**文档：改代码前先读。核心是一句话——**只做套壳，不做集成**。

## 1. 定位

| 项 | 说明 |
|---|---|
| 目标用户 | 想在桌面上一键用上 DSH、但不想自己折腾 Node 环境和命令行的人 |
| 交付物 | 单个 `dsh-desktop.exe`，首次运行自动把运行时装到旁边 |
| 不做的事 | 不改 DSH、不 fork、不打包 DSH、不提供 DSH 之外的 agent 能力 |

## 2. 为什么必须是「轻量套壳」

这是本项目最主要的设计取舍，原因不是"少写代码"，而是**兼容性隔离**：

1. **DSH 独立成进程。** DSH 以 `node <数据目录>/runtime/dsh/.../bin.js web` 的方式作为
   子进程运行，壳不链接、不加载、不解释它的任何 JS。DSH 崩溃、升级、换 Node 版本，
   都不需要重新编译壳。
2. **UI 来自 DSH 自己的 HTTP 服务。** 壳页面只有一个 `<iframe>` 指向本地反代地址；
   DSH 前端更新（新页面、新交互）**壳零改动**即可生效。壳不需要跟着改 UI 代码。
3. **桌面框架只承担窗口。** Wails/WebView2 只负责"显示一个 iframe"和托盘、窗口按钮。
   即使桌面框架出现渲染兼容问题，DSH 服务本身仍在正常监听——用户可以直接拿浏览器打开
   那个地址继续用。**这是"套壳"相对"集成"最大的好处：壳可以被绕过。**
4. **运行时不捆绑。** Node 与 DSH 在首次启动时下载安装（见
   [06-dependencies-and-versioning.md](06-dependencies-and-versioning.md)），
   所以 DSH 的版本跟进不依赖壳发版。

反面做法（明确不做）：把 DSH 前端打包进壳的 `frontend/`，或用壳的 IPC 直接调用 DSH 内部函数。
那样 DSH 每次改前端都要跟着重编壳，且桌面框架的兼容问题会直接变成"DSH 打不开"。

## 3. 职责边界

**壳负责**：

- 首次启动自举安装（Node zip + `npm install` DSH 到数据目录）；
- DSH 进程的生命周期：启动、就绪探测、重启、停止、异常退出上报；
- 进程树回收（Job Object，kill-on-close），保证不留孤儿 `node.exe`；
- 窗口、托盘、自绘标题栏；
- 会话 cookie 桥接（见 [02-architecture.md](02-architecture.md) 第 4 节）；
- 版本检查与一键更新。

**壳不负责**（属于 DSH 的领域，改了就越界）：

- DSH 的任何 UI、交互、业务逻辑；
- 修改 DSH 的源码或 `node_modules` 内容；
- 替 DSH 管理配置、会话、数据库。

## 4. 与 DSH 的契约

壳与 DSH 之间只有两个契约，二者都刻意做得很窄：

| 契约 | 位置 | 约定 |
|---|---|---|
| **就绪协议** | `internal/dsh/supervisor.go` 的 `readyLine` | DSH 在 stdout 打印 `dsh web: <URL>`，URL 含登录 token。壳按行正则解析。 |
| **HTTP** | `internal/proxy` | 就绪 URL 所在的 http 服务就是全部接口；壳只做透传与 cookie 附加。 |

另有一处**弱契约**（读了 DSH 前端的实现细节，但不改它）：

- 注入探针从 DSH 页面里读两个信息——文档背景亮度（判主题）、`AppFrame` 容器内联
  `style.gridTemplateColumns` 的第一列（判侧栏宽度），用于对齐壳的窗口按钮配色与拖动条位置。
- 这一处**必须容忍失效**：探针读不到就回退（侧栏宽度回退到贴左缘元素的实测宽度），
  再不行就不动，页面照常可用。**绝不允许因为探针失效而阻断页面加载**——`ModifyResponse`
  里任何错误都直接 `return nil`。

> 契约漂移怎么办：DSH 若改了就绪输出，**只改 `readyLine` 一处**；若改了 DOM 结构，
> 只影响主题/拖动条这两个装饰性行为。文档见 [06](06-dependencies-and-versioning.md) 第 5 节。

## 5. 失败隔离

| 失败点 | 期望行为 |
|---|---|
| Node / DSH 下载安装失败 | 壳不退出，浮层显示原因 + 重试按钮（`RetryBootstrap`） |
| DSH 启动超时（`defaultReadyTimeout` = 45s）或就绪前退出 | 终止并回收进程树，上报 `StatusError`，用户可重试或重启 |
| DSH 运行中意外退出 | 上报状态，壳保持存活，托盘 menu 可重启 |
| 反代目标未接线 | 返回 503 + 中文提示，而不是白屏 |
| 探针注入失败 | 忽略，页面正常返回 |
| DSH 更新（`npm install`）失败 | **旧版本保持完好**，重新启动旧版继续用，不把用户卡死 |

原则：**任何单点失败都不能让用户"什么都打不开"**。可降级就降级，可重试就给重试。

## 6. UI 规范

### 窗口

- 无边框（`Frameless: true`），默认 1180×800，最小 720×480；
- 窗口装饰由前端自绘（右上角最小化 / 最大化 / 关闭）；
- 拖动区是顶部 `--wails-draggable` 条带，**其左边界随 DSH 侧栏宽度动态右移**，
  避免遮住 DSH 自己的侧栏折叠按钮。逻辑：`left = 侧栏宽度 + 8px`；
- 关闭按钮 = **隐藏到托盘**（`HideWindowOnClose` + `WindowHideToTray`），不退出进程。
  真正退出只走托盘「退出」。

### 托盘

- 原生 Win32 实现，不用第三方 systray 库（原因见 [02](02-architecture.md) 第 6 节）；
- 菜单：显示主窗口 / 重启服务 / 关闭服务 / 检查更新 / 分隔线 / 退出；
- 左键单击与双击 = 显示主窗口；右键 = 菜单；
- 菜单动作必须异步派发（重启/停止要等子进程退出，同步执行会卡死消息循环）；
- 退出时摘掉图标，不留幽灵托盘项。

### 图标

数值是**量出来的**，不要凭感觉改：

| 项 | 取值 | 依据 |
|---|---|---|
| 画布 | 满格、**零内缩** | 实测 150% 缩放下 `SM_CXSMICON=24`；微信绿色方块与相邻的白色徽标实测都是 24×24，即托盘图标内容填满整个单元格 |
| 圆角半径 | 边长的 22% | 微信实测约 15%，白色徽标接近圆形；22% 是 Fluent 风格圆角方块的中位取值 |
| 鲸鱼宽度 | 边长的 64%，等比居中 | 微信内层白色气泡约占 65%；0.70 会顶到圆角，0.58 偏小 |
| 颜色 | 方块 `#FFFFFF`、鲸鱼 `#232323`，无描边 | 鲸鱼色采样自设计稿；浅色任务栏（实测约 `#E5DDEE`）上白色对比足够，加描边反而脏 |

产物与尺寸：

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `build/tray.ico` | 16/20/24/32/48 | 托盘（全 DIB） |
| `build/windows/icon.ico` | 16/20/24/32/48/64/128/256 | exe 与任务栏窗口（≥128 用 PNG 压缩） |
| `build/appicon.png` | 1024 | Wails 图标源 |
| `build/dsh-logo.svg` | — | 鲸鱼矢量路径源文件（形状的唯一真源） |

小尺寸（16px）下鲸鱼会糊成深色块，这是必然的（QQ 的企鹅在 16px 同样糊）；托盘实际使用
的 24px 一档是清晰的。

### 状态呈现

主界面尽量"什么都没有"：只有 iframe、顶部拖动条、右上角三个按钮。安装/更新进度走浮层，
DSH 就绪后浮层消失。**壳不打扰 DSH 的界面**。

## 7. 日志规范

| 输出 | 去向 |
|---|---|
| DSH 子进程的 stdout / stderr | `runtime:log` 事件 → 浮层日志区（仅浮层可见时追加） |
| 壳自身的托盘/窗口日志 | `<数据目录>/tray.log`（同时尝试写 stderr） |
| 反代错误 | `log.Printf`（GUI 进程无控制台，实际只落到调试器） |

**硬约束**：`wails build` 产出的是 windowsgui 子系统进程，**没有 stdout/stderr**。
所以：

- 不要依赖 `fmt.Println` / `log.Printf` 给用户或给未来的自己留线索——用户看不到；
- 需要留痕就写文件，且**不要用 `io.MultiWriter(os.Stderr, f)`**：它遇到第一个失败的
  writer 就整体返回，GUI 进程写 stderr 必然失败，日志文件会一直停在 0 字节。
  用 `tray_windows.go` 的 `teeWriter`（逐个写、忽略个别失败）。

## 8. 命名与提交

- 提交信息：英文 conventional commits，`feat(scope): ...` / `fix(scope): ...`，
  scope 用受影响的模块（`tray` / `proxy` / `bootstrap` / `icon` / `docs` …）；
- 正文写**为什么**，不是"改了什么"——`git log` 已经能看出改了什么；
- 文档类改动单独成一个 `docs:` commit，不要和代码混在一起；
- 代码注释用中文，与现有风格一致。
